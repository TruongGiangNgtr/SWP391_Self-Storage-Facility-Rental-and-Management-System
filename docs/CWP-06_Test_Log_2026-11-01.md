## 4. Open issues and observations

### ISSUE-CWP06-001 — Visit filtering limited to current page

**Suggested severity:** Medium (usability / discoverability)  
**Observed:** In My Visits, 663 records were distributed over pages; selecting Access Visit returned 0 matches on one page although another page showed 17 matches. UI explicitly states filters and tab counts cover the current page only. My Visits navigation from Contract Details did not automatically scope Visits to that Contract.  
**Impact:** Customer cannot readily retrieve a comprehensive Visit history for a chosen Contract; page-local filtering may falsely suggest there are none.  
**Recommendation:** Evaluate server-side filtering before pagination, or add a Contract-specific Visit History view using the available `visits` field. Preserve authorized scope.  
**Status:** Open observation; not proven API defect.

### ISSUE-CWP06-002 — Extension History not visible / positive data absent

**Suggested severity:** Major if the feature truly cannot show historical extensions  
**Observed:** No Extension History / Renewal History section visible on inspected Contract detail and extension form. All three inspected Contract detail responses contained `extensions: []`.  
**Impact:** CWP-06 explicitly calls for viewing ContractExtension history; empty-array serialization does not validate nonempty history rendering.  
**Recommendation:** Prepare at least one Contract with a persisted extension, confirm `GET /contracts/{id}` returns a nonempty `extensions` list, and test its rendering with appropriate ordering and dates. Do not mutate shared/paid data without authorization.  
**Status:** Open — insufficient coverage; not a confirmed backend defect.

### ISSUE-CWP06-003 — Potentially misleading return guidance on completed Contract

**Suggested severity:** Low (content/UX)  
**Observed:** A `COMPLETED` Contract with Settlement `FINALIZED` and Return Visit `CHECKED_IN` still displayed general copy that a pending RETURN Visit blocks ACCESS Visits and renewal.  
**Impact:** May confuse the user about whether return is already completed.  
**Recommendation:** Show context-sensitive explanatory copy based on Contract and settlement state; verify whether Return Visit remaining `CHECKED_IN` is intentional in the approved lifecycle.  
**Status:** Needs requirement review; no confirmed lifecycle defect.

### OBS-CWP06-004 — Demo billing data and fee timing

The screen showed invoices for 2027 while the test was run on 01/11/2026, and a late-fee record calculated at 01/11/2026 with 27 overdue days. The user did not establish which invoice this fee references. No billing bug is claimed from these observations alone; further testing would require invoice linkage and seed/job policy verification.

## 5. Coverage gaps / follow-up

1. Nonempty ContractExtension history, persisted and correctly displayed, remains **NOT TESTED**.
2. Contract-scoped Visit History in the UI remains **PARTIAL**; an API `visits` array is available but the dedicated display was not observed.
3. Invoice detail navigation, invoice-to-late-fee linkage and financial calculation/persistence were **not** independently verified.
4. Return workflow transitional states (new RETURN, Inspection pending, Damage pending, settlement not finalized) were **not** exercised. Only active empty state and completed populated state were checked.
5. API-level unauthenticated request, employee-role restrictions and authorization for billing/return-summary endpoints were **not** part of this CWP-06 run. Cross-customer Contract detail read was checked.
6. Pagination/filtering across the full Contract list (318 total), beyond the demonstrated list display, was **not** fully verified.
7. UI not-found case passed, but its API status was not captured.

## 6. Final assessment

**CWP-06: PARTIAL PASS — NOT READY FOR FULL ACCEPTANCE.**

The tested UI successfully displayed multiple Contracts, specific Physical Units, rent periods, sampled billing status, and active/completed return progress. The cross-customer Contract read was denied by the backend (`404 RESOURCE_NOT_FOUND`). Full CWP-06 acceptance remains pending proof that Customer can access Visit and ContractExtension histories **for the relevant Contract**, including at least one nonempty Extension history example. Issues CWP06-001 through CWP06-003 should be reviewed separately rather than classified automatically as backend defects.
