## Defects / issues

### BUG-CWP05-001 — Cancel Reservation Visit independently is blocked

- **Status:** Open — requirement/business-rule discrepancy.
- **Severity proposed:** Major (confirm with project owner).
- **Precondition:** Authenticated owning Customer; linked Reservation `CONFIRMED`; RESERVATION Visit `SCHEDULED`.
- **Reproduction:** My Visits → scheduled Handover Visit → Cancel Visit → enter valid reason → Confirm.
- **Observed:** HTTP `409 Conflict`:

```json
{
  "code": "RESERVATION_VISIT_CANCEL_NOT_ALLOWED",
  "message": "Reservation Visit cannot be cancelled independently. Cancel the Reservation instead.",
  "errors": null
}
```

- **Requirement conflict:** CWP-05 states `Select, reschedule, or cancel the RESERVATION Visit within day 1–5 of Start Month while the Visit remains SCHEDULED.` Backend explicitly prohibits standalone cancellation and offers parent Reservation cancellation. **Do not change policy by assumption:** request owner clarification on whether Visit-only cancellation is intended or UI must direct users to Cancel Reservation.
- **Code location inspected:** `backend/Frms.Business/Services/Implementations/VisitService.cs` (`CancelCoreAsync`, mapping `RESERVATION_VISIT_CANCEL_NOT_ALLOWED` to 409); API route `POST /api/v1/visits/{visitId}/cancel` in `VisitsController.cs`.

### BUG-CWP05-002 — Stale Reschedule error appears in Cancel Visit modal

- **Status:** Open — UI state defect.
- **Severity proposed:** Minor (usability/incorrect error attribution).
- **Reproduction:** Reschedule to invalid `2027-01-06` → get date-policy validation error → close Reschedule → open Cancel Visit.
- **Observed:** Cancel modal still displays `This date is not available for your visit...` despite the current operation asking for a cancellation reason. Later a new 409-related message appears after submit.
- **Expected:** Opening Cancel Visit should reset action-specific error state, preserving only relevant cancellation validation messages.

### Observation — Deposit remains marked PAID after Reservation cancellation

Deposit Invoice was still displayed as `PAID` following cancellation. This may correctly preserve historical payment status; **not a verified bug**. Refund and settlement policy, related transaction entries, and any future adjustment were not tested.
