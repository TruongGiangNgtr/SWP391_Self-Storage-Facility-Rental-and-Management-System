## 1. Requirement and scope

Allow a CUSTOMER to renew an ACTIVE Contract by selecting a New End Month later than the current End Month. Extension months must be contiguous, pass capacity validation, and create a persisted ContractExtension record. Renewal is prohibited for non-ACTIVE Contracts and Contracts with pending RETURN Visits. Validate input and enforce authentication and ownership.

## 4. Backend defect — fixed and retested

### BUG-CWP09-001 — Missing New End Month produces HTTP 500

- **Date discovered / retested:** 2026-11-02
- **Severity:** Major; **Priority:** High (proposed)
- **Initial state:** OPEN; **final state:** **FIXED / RETEST PASS**
- **Endpoint:** `POST /api/v1/contracts/{contractId}/renew`
- **Reproduction:** Customer bearer token with an owned ACTIVE Contract; body `{}`.
- **Expected:** HTTP 400 with a meaningful `VALIDATION_ERROR` and no extension creation.
- **Before fix:** HTTP 500, `INTERNAL_SERVER_ERROR`, “An unexpected error occurred.”
- **Backend trace:** `System.NullReferenceException` in `Frms.Api.Controllers.ContractsController.RenewContract`, `ContractsController.cs:line 83`.
- **Fix performed (as reported in testing session):** `RenewContractRequest` adjusted; `RenewContract` action amended to guard missing/null `request` and `NewEndMonth` and validate the `YYYY-MM` format before calling renewal logic. This describes observed/tested behavior; not an independent source diff verification.
- **Retest:** `{}` and `null` each HTTP 400 / `VALIDATION_ERROR` / “New End Month is required.”; `invalid-month` and `2027-13` each HTTP 400 / `VALIDATION_ERROR` / “New End Month must use YYYY-MM format.”
- **Conclusion:** Defect fixed for all four observed invalid input cases. No HTTP 500 remains among those four.

## 7. Capacity test limitation and authorization findings

- `GET /api/v1/facilities/569cd7fe-dba4-462e-a357-5a1880116480/storage-units` returned HTTP 403 `FORBIDDEN` for the tested Customer/BOM/Admin credentials.
- Source inspection showed `[Authorize(Roles = RoleNames.FacilityManager)]` on the list endpoint. This is expected role restriction and **not** a confirmed bug.
- The PostgreSQL routine `usp_RenewContract` calculates monthly capacity from Storage Units with statuses AVAILABLE/IN_USE/INSPECTION, active reservation holds, and overlapping ACTIVE Contracts. It throws `RENEWAL_CAPACITY_NOT_AVAILABLE` where capacity <= holds + occupied, mapped to HTTP 409.
- **No actual capacity shortage was created or observed.** SQL readback could not proceed because only a SQL Server query console was available (PostgreSQL-specific `::` syntax failed); the user requested this branch be skipped rather than setting up Docker/PostgreSQL tooling.
- **CWP09-08B must remain NOT TESTED**, not PASS. A future controlled database fixture or integration test should assert 409, unchanged Contract End Month and no new ContractExtension after failure.
