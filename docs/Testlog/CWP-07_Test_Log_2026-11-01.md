## Bugs and issues

### BUG-CWP07-001 — Invalid or missing `visitDate` causes HTTP 500 (FIXED / RETEST PASS)

**Severity (original):** Major; **priority (original):** High; **status:** **FIXED — verified by manual Postman retest on 2026-11-01**; **layer:** Backend API.  
**Endpoint:** `POST /api/v1/contracts/084c1ace-cf3a-4994-b5ba-963ef041a6c0/access-visits`  
**Preconditions:** Owner Customer token and ACTIVE contract, `Content-Type: application/json`.

| Input | Before fix | After fix, observed | Verdict |
|---|---|---|---|
| `{}` | HTTP 500 `INTERNAL_SERVER_ERROR` | HTTP 400 `VALIDATION_ERROR`; `Visit date is required.` | PASS |
| `{"visitDate":null}` | HTTP 500 `INTERNAL_SERVER_ERROR` | HTTP 400 `VALIDATION_ERROR`; `Visit date is required.` | PASS |
| `{"visitDate":"invalid-date"}` | HTTP 500 `INTERNAL_SERVER_ERROR` | HTTP 400 `VALIDATION_ERROR`; `Visit date is required or invalid.` | PASS |

**Root cause confirmed in runtime log:** `System.NullReferenceException` in `ContractAccessVisitsController.CreateAccessVisit` at `ContractAccessVisitsController.cs:line 24` when malformed JSON resulted in `request == null` and code dereferenced `request.VisitDate`.  
**Fix applied locally by user:** Updated ACCESS request handling to validate nullable/missing date and guard `request is null`, returning HTTP 400 rather than dereferencing null. The precise final local diff has **not** been independently reviewed; this is a behaviorally verified fix.  
**Build evidence:** `dotnet build` completed successfully in 14.3 s (2026-11-01).  
**Retest evidence:** Three Postman screenshots from 2026-11-01. The invalid-format retest returned HTTP 400 with `VALIDATION_ERROR`, trace `0HNPO35J1S1B6:00000001`.  
**Remaining:** Add automated regression tests for missing/null/malformed JSON and verify API creation `201 Created`; do not treat those as completed.
